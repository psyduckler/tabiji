## 1. What Tabiji Actually Is

A **static HTML site** deployed on Cloudflare Pages. No framework (Next.js is in ARCHITECTURE.md but was never adopted). Every page is a self-contained `index.html` with inline `<style>` and `<script>`. No shared CSS files, no JS bundles, no build step.

**Deploy flow:** `git push` → GitHub → Cloudflare Pages auto-builds from `main` branch. That's it. `deploy.sh` is now just a clean-tree push helper for that commit-based production flow.

## 3. Architecture — How It Actually Works

### 3.1 Page Types & Templates

Every page is **fully self-contained HTML** with inline CSS. There are NO shared stylesheets or component libraries. Each page type has its own design system embedded via CSS variables:

```
:root {
  --indigo: #1a1a2e;
  --sand: #c2b280;
  --cream: #faf8f5;
  --text-muted: ...
}
```

**Page types and their generation sources:**

| Type | Generated by | Template/Generator |
|---|---|---|
| `/i/` (paid itineraries) | `functions/fulfill-order.js` | `functions/generate-itinerary-html.js` |
| `/popular-picks/` | Sub-agents (ad hoc) | Inline HTML in agent prompt |
| `/compare/` | Sub-agents (ad hoc) | Inline HTML in agent prompt |
| `/itineraries/` | Sub-agents (ad hoc) | Varies |
| `/alerts/` | `functions/build-travel-alerts.py` | Script generates all 216+ pages |
| `/best-places-to-visit-in-*` | Sub-agents | `best-places-template.html` as reference |
| `/resources/` | Manual/sub-agents | No shared template |
| Landing pages | Hand-crafted | `index.html`, `plan.html`, `success.html` |

### 3.2 Navigation & Footer

Every page has its **own copy** of the nav and footer baked in. The nav includes:
- Logo link to `/`
- "Explore" dropdown (Compare, Finder, Spin, Resources, Owl)
- "Plan My Trip" CTA → `/plan.html`

Footer includes: Terms, Privacy, Delete Data, social links (IG, YT, Pinterest, X), Media Studio, API.

**⚠️ Changing the nav/footer means updating 1,049 pages.** There is no shared include system.

### 3.3 Images & Media

- **ALL images served from Cloudflare R2** via `https://img.tabiji.ai/`
- The git repo has **no content images** — only HTML/CSS/JS
- R2 key structure mirrors repo: `i/{slug}/hero-bg.jpg`, `popular-picks/{slug}/{photo}.jpg`, etc.
- Exception: `img/` dir has some Instagram Reel videos (legacy, ~52MB — should probably be cleaned)
- Google Maps embeds use API key `AIzaSyBP0yidMjJEECgkIiZz2lw1NLsQ7jdASYc`

### 3.4 Order Fulfillment Pipeline

```
Stripe webhook → orders/pending.json → Psy claims order →
  fulfill-order.js runs:
    1. generate-slug.js (unique slug)
    2. generate-itinerary-html.js (full HTML page)
    3. day-photos.js (hero image via AI)
    4. git add + commit + push
    5. Poll Cloudflare until page returns 200
    6. send-email.sh (Resend, from hello@tabiji.ai)
    7. Move order from pending.json → fulfilled.json
```

**Locking:** `fulfill-order.js` uses atomic mkdir (`.fulfillment.lockdir/`) to prevent concurrent fulfillments.

**Git hook:** `.githooks/pre-commit` rejects new `/i/` pages without a `hero-bg.png` or `hero-bg.jpg`.

### 3.5 Enrichment Pipeline (Popular Picks)

After creating a popular-picks page:
1. `functions/enrich-popular-picks.py` — Google Places data (ratings, hours, Maps links)
2. `scripts/aeo-upgrade-popular-picks.py` — AEO answer-first + JSON-LD
3. `functions/add-related-links.js` — cross-links
4. Git commit + push

### 3.6 API Layer

Static JSON API at `/api/v1/` — 1,428 pre-built JSON files, ~18MB. Built by `api/build-api.py`. Zero runtime cost.

### 3.7 Queue Files (Root)

## 4. 🚫 OFF-LIMITS — Do Not Touch

These paths are **critical production infrastructure**. Do not modify, move, rename, or refactor:

### 4.1 Fulfillment Pipeline (REVENUE PATH)
- **`functions/fulfill-order.js`** — The single entry point for all paid order fulfillment. Any change risks breaking customer delivery.
- **`functions/generate-itinerary-html.js`** — HTML generator for paid itineraries. 285 live pages depend on this template's output format.
- **`functions/generate-slug.js`** — Slug generation. Changing slug format breaks URL permanence.
- **`functions/day-photos.js`** — Hero image generation. Skipping this = blank hero on customer pages.
- **`functions/send-email.sh`** — Email delivery to customers. Misconfigured = lost revenue.
- **`functions/wait-for-deploy.sh`** — Deploy verification. Removing this = customer gets 404 link.
- **`functions/email-template.js`** — Email formatting.
- **`orders/pending.json`** — Live order queue. Corruption = lost orders.
- **`orders/fulfilled.json`** — Order history/receipts.
- **`.githooks/pre-commit`** — Safeguard against incomplete itineraries.
- **`.fulfillment.lockdir/`** — Runtime lock, never commit or delete manually.

### 4.2 Live Content Pages (1,049 HTML pages)
- **`/i/*/index.html`** — 285 paid customer itineraries. These are delivered products.
- **`/popular-picks/*/index.html`** — 381 SEO pages driving organic traffic.
- **ALL existing `index.html` files** — Every page is a live URL. Renaming/moving = broken links + lost SEO.
- **`index.html`** (root) — Landing page. Live, converting customers.
- **`plan.html`** — Order form page. Revenue-critical.
- **`success.html`** — Post-payment page.

### 4.3 API
- **`api/`** — Static JSON API. External consumers may depend on these URLs.
- **`.well-known/`** — Agent discovery files. AI tools use these.

### 4.4 Queue Files
- **Any `*.json` queue file in root** — Active batch processing queues. Cron jobs read/write these.

### 4.5 Config & Deploy
- **`deploy.sh`** — Deploy script.
- **`.githooks/`** — Git hooks that prevent broken deploys.

## 6. What SHOULD Be Refactored (Opportunities)

### 6.1 High-Value, Low-Risk

| Area | Problem | Suggested fix |
|---|---|---|
| **`scripts/` clutter** | 126 files, 109 are one-off `fulfill-order_*.js` from past orders | Archive to `scripts/archive/` or delete. These are historical artifacts, not reusable. |
| **`functions/run-*.js` clutter** | 30 one-off fulfillment scripts | Archive to `functions/archive/`. Same as above. |
| **`img/` directory** | 52MB of Instagram Reel videos in git | Move to R2, delete from repo. These don't belong in git. |
| **Root queue files** | 7 JSON queue files cluttering root | Move to `queues/` directory (update all cron job references) |
| **Root `.txt` verification files** | `16cf000a...txt`, `40acce16...txt`, etc. | Identify purpose (likely domain verification), document or clean |

### 6.2 Medium-Value, Medium-Risk

| Area | Problem | Suggested fix |
|---|---|---|
| **Shared nav/footer** | 1,049 pages each with their own copy | Extract to a `_includes/` pattern with a build script that injects shared HTML. Allows single-point nav updates. |
| **Shared CSS variables** | CSS vars duplicated in every page | Extract common `:root` vars + base styles to a shared CSS file. Pages can still have page-type-specific styles inline. |
| **Template standardization** | Popular-picks, compare, itineraries each generated differently | Create formal HTML templates per page type in `templates/` |

### 6.3 Low-Priority / Future

| Area | Problem | Suggested fix |
|---|---|---|
| **No build system** | Everything is raw HTML, no preprocessing | Consider a lightweight static site generator (11ty/Hugo) — but this is a BIG change |
| **`orders/` directory** | Contains both data files and one-off scripts | Clean: data in `orders/`, scripts should be elsewhere |

## 7. Refactor Ground Rules

1. **Branch everything.** Work on `refactor/phase-N` branches. Never commit directly to `main`.
2. **No URL changes.** Every existing URL must continue to work. Zero broken links.
3. **Test deploy before PR.** Use `wrangler pages deploy . --project-name tabiji --branch refactor-test` to test on a preview URL.
4. **Don't touch fulfillment.** The `functions/fulfill-order.js` pipeline and its dependencies are off-limits unless Bernard explicitly approves.
5. **Don't modify live content.** Existing HTML pages are delivered products. Structural refactors (shared nav, CSS extraction) must produce byte-identical rendered output.
6. **Small PRs.** Each phase = one PR. Don't bundle unrelated changes.
7. **Document what you did.** Update this file with completed phases.

## 8. Suggested Phase Plan

- Archive `scripts/fulfill-order_*.js` → `scripts/archive/`

- Create `_includes/nav.html` and `_includes/footer.html`
- Build script: `scripts/inject-includes.py` — replaces nav/footer in all pages from `_includes/`

### Phase 3: Shared Assets
- Extract common CSS variables to `assets/css/variables.css`
- Extract common base styles to `assets/css/base.css`
- Update templates to reference shared CSS
- Run injection script to update all pages

### Phase 4: API & Build Pipeline
- Formalize `api/build-api.py` as part of a documented build step (with explicit Python dependencies in `api/requirements.txt`)
- Add a `Makefile` or `package.json` scripts for common operations
- Document the full build/deploy pipeline
