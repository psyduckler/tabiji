## Decision framing

The system is now operational enough to support a controlled production cutover decision.

What is true now:
- both major Popular Picks families have source models
- both have extractors
- both have renderers
- both have batch backfills
- both have validation/build paths
- both have representative parity checks

## Recommendation

Proceed with a **controlled first production cutover**, not a broad cutover.

Suggested candidates:
- leaf: `shinjuku-cheap-restaurants`
- hub: `italy`

The right standard is:
- regenerate to temp path
- compare against live
- if acceptable, write generated output to the real page path on a branch
- review diff before merge

That is now a practical workflow, not a hypothetical one.
